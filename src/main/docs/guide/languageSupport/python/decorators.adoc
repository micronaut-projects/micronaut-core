Java annotations are applied to Python classes, functions and parameters as decorators, and as `Annotated[...]` metadata. Whether a decorator is applied bare or called follows from how it is written, as for a Java annotation: `@Singleton` and `@Singleton()` are the same annotation, and every argument of a call is an annotation value. A single positional argument is the `value` member, whatever its type:

[source,python]
----
from org.junit.jupiter.api import MethodOrderer, Test, TestMethodOrder

@TestMethodOrder(MethodOrderer.OrderAnnotation)  # <1>
class OrderedTest:

    @Test  # <2>
    def first(self):
        pass
----

<1> The class `MethodOrderer.OrderAnnotation` is the `value` of the annotation, as `@TestMethodOrder(MethodOrderer.OrderAnnotation.class)` is in Java
<2> A bare decorator is the annotation without members

== Dataclass Field Validation

Python dataclasses can declare validation constraints through the standard-library `field(metadata=...)` extension point, without importing constraint annotations:

[source,python]
----
from dataclasses import dataclass, field

@dataclass
class Contact:
    name: str = field(metadata={
        "validation": {
            "not_blank": True,
            "size": {"min": 1, "max": 80, "message": "Use 1 to 80 characters"},
        }
    })
----

The compiler generates introspection for Python dataclasses automatically; an explicit `@Introspected(...)` is only needed to customize its configuration. This does not add serialization or database-mapping annotations.

The compiler reads literal validation metadata and supported compile-time constants; it does not execute expressions to determine annotation values. It translates the `validation` dictionary to the existing Jakarta validation metadata. Use Micronaut Validation to enforce it at validation boundaries; ordinary Python construction such as `Contact("")` does not run validation automatically. A metadata-only field remains a required constructor argument. Explicit `default` and `default_factory` values keep their dataclass meaning.

Set a constraint to `True` to enable its defaults, or `False` to disable it. A dictionary supplies annotation options. Constraints with required options must provide them; for example, `"min": {"value": 0}`. Numeric zero is a bound, not a disabled constraint. `"assert_false": True` enables the constraint requiring a false value.

[%header,cols="2,3"]
|===
|Constraint keys |Additional options

|`not_blank`, `not_empty`, `not_null`, `null`
|None

|`positive`, `positive_or_zero`, `negative`, `negative_or_zero`
|None

|`assert_true`, `assert_false`
|None

|`past`, `past_or_present`, `future`, `future_or_present`
|None

|`size`
|`min`, `max`

|`min`, `max`
|Required integer `value`; an integer shorthand such as `"min": 0` is also supported

|`decimal_min`, `decimal_max`
|Required string `value`, optional `inclusive`; a string shorthand such as `"decimal_min": "0.01"` is also supported

|`digits`
|Required `integer` and `fraction`

|`pattern`
|Required `regexp`, optional `flags`; a string shorthand such as `"pattern": "[A-Z]+"` is also supported

|`email`
|`regexp`, `flags`
|===

Constraint options also include `message`, `groups`, and `payload`. Regular expressions and flags retain Jakarta/Java semantics, not Python `re` semantics; flag names are strings such as `"CASE_INSENSITIVE"`. Temporal, null, and whitespace checks likewise use the existing validators, without coercing or stripping Python values. Repeating a constraint with a list of member dictionaries is not supported.

Use `"valid": True` for cascaded validation of an introspected nested object; `valid` has no constraint options. Unknown constraint names, unknown options, missing required options, and malformed recognized validation metadata are compilation errors. Other metadata namespaces are left alone. Method parameters continue to use `Annotated[...]` metadata.

== Custom Annotations

A custom annotation is a function returning a decorator, itself decorated with the annotations that make up its stereotype. Its parameters are the annotation members and their defaults the member defaults. It is applied like a generated decorator, bare or called, in the module that defines it and in modules that import it:

[source,python]
----
from jakarta.inject import Qualifier

@Qualifier
def Cylinders(value: int = 4):
    def decorator(target):
        return target
    return decorator

@Cylinders        # value = 4
class FourCylinderEngine:
    pass

@Cylinders(8)
class V8Engine:
    pass
----

A function with exactly one required positional parameter (or only `*args`) receives the decorated target when it is applied bare, as any Python decorator does; it is never rewritten to a call. That is the plain decorator returning the target (`def Timed(target): return target`), the wrapping decorator below, and an annotation whose member has no default (`def Tagged(value: str)`), which is written `@Tagged("x")`:

[source,python]
----
from micronaut.core.bind.annotation import Bindable

@Bindable
def Traced(func):
    def wrapper(*args, **kwargs):
        return "traced:" + func(*args, **kwargs)
    return wrapper

@Traced   # Traced(hello), never Traced()(hello)
def hello(self) -> str:
    return "ok"
----

A custom annotation function whose members are only `*args` (`def Tags(*values: str)`) is likewise a function with only `*args`: written `@Tags("a", "b")` or `@Tags()` it is the annotation with those values, but applied bare it receives the decorated target as its only value, like any Python decorator, and the compiler does not rewrite it. Give such an annotation a regular member with a default instead when it is meant to be applied bare.

A generated decorator applied bare through a name the compiler cannot see as the annotation (`Bean = Singleton` in another module, `getattr`) receives the class or function as its single argument; unless the annotation's `value` member holds a class, it raises a `TypeError` naming the annotation rather than replacing the target with the decorator.

== Placeholder Bodies

A method whose body is only `...` is abstract where Python itself would not instantiate the class, and where the method is implemented by Micronaut:

* in a class extending `abc.ABC` or `typing.Protocol`, or when decorated with `@abstractmethod`;
* in a class carrying an api:aop.Introduction[] stereotype, such as a declarative HTTP client, a Micronaut Data repository or an AI service, whose methods are implemented by the introduction advice.

A docstring before the `...` documents the declared method and keeps the body a placeholder:

snippet::micronaut.docs.placeholders.BookClient[tags="imports,class", indent=0, title="A documented placeholder method"]

A body of `pass`, or one raising `NotImplementedError`, is not a placeholder: such a method is a concrete method with that body.

In any other class the placeholder is a method body that returns `None`, so a concrete bean whose methods are placeholders, such as a messaging listener written before its handlers, is a concrete, injectable bean:

[source,python]
----
from jakarta.inject import Singleton
from micronaut.context.annotation import Executable

@Singleton
class MessageListener:
    @Executable
    def on_message(self, message: str) -> None:
        ...
----
