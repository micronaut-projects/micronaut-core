Java collections cross into Python by reference. A `java.util.List`, `Map` or `Set` that is injected into a Python bean, passed to a Python method, or assigned to an attribute of a Python object is the Java object itself, exposed by GraalPy as a foreign list, dict or set: it keeps its class, its identity and its full Java API, and changes made in Python are visible from Java.

[source,python]
----
from typing import Annotated

from com.example.cache import NamedCache  # a Java Map implementation with an API of its own
from jakarta.inject import Inject, Singleton


@Singleton
class PeopleService:
    people: Annotated[NamedCache[str, Person], Inject]

    def add(self, person: Person) -> str:
        self.people.put(person.getId(), person)   # the Java API of the injected map
        self.people[person.getId()] = person      # or the Python dict protocol
        return self.people.getName()
----

A map-like Java object such as a cache or a view is never copied or iterated when it enters Python. Only a plain JDK collection (an `ArrayList`, a `HashMap`, a `List.of(...)`, ...) that holds values needing conversion, generated Python classes, `java.time` values or nested collections of those, is rebuilt so its elements arrive as Python objects.

Since the collection is shared, in-place mutation works in both directions: a `list[str]` attribute of a Python dataclass that was stored in Java, for example in an HTTP session, and read back as its generated Java class can be mutated with `append` and the Java side sees the change. The same is true of immutability: appending to a `List.of(...)` raises the Java exception. A Java `Set` is a foreign iterable in Python: it can be iterated and its Java methods (`size()`, `contains(...)`, `add(...)`) called, but `len()` and `in` are not available.
