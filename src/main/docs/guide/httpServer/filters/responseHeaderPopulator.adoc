The api:http.server.filter.ResponseHeaderPopulator[] interface provides a lightweight way to add response headers without implementing a complete api:http.filter.HttpServerFilter[].

Register an implementation as a bean. The `findHttpHeaders` method receives the current api:http.HttpRequest[] and api:http.HttpResponse[] and returns the headers to add:

snippet::io.micronaut.docs.server.filters.SecurityHeaderPopulator[tags="imports,clazz", indent=0, title="A ResponseHeaderPopulator example"]

<1> The `@Singleton` annotation registers the populator as a bean.
<2> `findHttpHeaders` receives the current request and response.
<3> Each api:http.HttpHeaderEntry[] contains a response header name and value.

The HTTP server invokes each `ResponseHeaderPopulator` for every response. Return `null` when no headers apply to the request and response. If the response already contains a returned header, its existing value takes precedence.

`ResponseHeaderPopulator` extends api:core.order.Ordered[]. If multiple populators are registered, implement `getOrder()` to control their invocation order.

Micronaut's built-in support for the Cross-Origin-Embedder-Policy and Cross-Origin-Resource-Policy response headers uses response header populators. See <<corsCrossOriginEmbedderPolicy, Cross-Origin-Embedder-Policy>> and <<corsCrossOriginResourcePolicy, Cross-Origin-Resource-Policy>>.
