Handler routes read `application/x-www-form-urlencoded` and `multipart/form-data` forms in three ways: collected by a synchronous form handler, collected by an asynchronous handler, or streamed part by part.

snippet::io.micronaut.docs.server.functional.FormRoutes[tags="imports,clazz", indent=0, title="Forms and file uploads"]

<1> A api:web.router.builder.FormRequestHandler[] receives the whole form as api:http.form.FormData[]. Its accessors convert the text fields (`getString`, `getInt`, `getInt(name, defaultValue)`, `findInt`, `getValues`, ...). A missing or unconvertible field is answered with `400`, see api:http.form.FormFieldException[]. The route consumes both form media types.
<2> An asynchronous handler collects the form with `request.form()`.
<3> The uploaded files of a collected form are api:http.form.FileUpload[] handles: `bytes(int)`, `transferTo(Path)`, `transferTo(OutputStream)` or `takeBody()`, each once. `getFile` answers `400` when the file is missing or the field is a text field. On a synchronous route that runs on an executor, `readAllBytes()` and `readString()` read a received file in a blocking way.
<4> `request.parts()` streams the form: api:http.form.FormParts[] hands each api:http.form.FormPart[] to a consumer as it arrives, without collecting the form. `forEach` visits every part; `part(name, consumer)` skips to the named part and completes with `false` when the form has none.
<5> A file part is read like a collected file, here streamed to a new file. The part belongs to the consumer until the stage it returns completes; then it is closed, and what the consumer did not read is discarded.

Uploads are limited like the uploads of controllers: `micronaut.server.multipart.max-file-size` for each file, and `micronaut.server.max-request-buffer-size` for the text fields a collected form holds in memory. A collected form stores large files on disk according to the multipart configuration, and the files it still owns are deleted when the request ends, or when `FormData.close()` is called. `transferTo(Path)` writes a temporary file next to the destination and moves it into place, so a failed or aborted transfer leaves no file behind, and an existing file is never replaced.

TIP: Never use the file name sent by the client as a path on the server: generate the name, as in the example, or sanitize it.

`FormData` and `FormParts` are also bound as arguments of controller methods.
