A lambda has no method annotations. Use `annotate(...)` when a route needs metadata for features such as filter matching, API versioning, CORS, executor selection or Micronaut Security.

For example, `annotate(Audited.class)` adds an annotation without members, and `annotate(Version.class, version -> version.value("2"))` supplies a value. You can also pass an `AnnotationValue` and chain calls to add more annotations.

Annotations on a group apply to its routes and nested groups. More specific declarations override the annotation members they set.

=== Reusing Bean Metadata

Use `annotationMetadata(provider)` to reuse an annotated element's metadata. An `ExecutableMethod` also identifies the bean method represented by the route, enabling integrations such as local `@Error` handlers. A bean definition supplies annotations only.

The handler still determines the arguments, execution and result. Supplying metadata does not invoke the bean method in place of the handler.

For framework integrations, a handler can implement api:web.router.builder.RouteMethodProvider[] to supply its `ExecutableMethod`. An explicit `annotationMetadata(...)` on the route takes precedence. Lambdas do not infer a bean method automatically.

=== Runtime Metadata Limitations

Annotations added at runtime do not automatically include their meta-annotations. Features that look up the annotation directly can use it; features that depend on a stereotype need that stereotype supplied through `AnnotationValueBuilder.stereotype(...)`.

Annotation expressions require compile-time processing. Use `where(...)` for handler-route conditions instead of adding `@RouteCondition` dynamically.
