The terminal `resources(...)` ends a `GET` route with a handler of the resources under its URI: the route serves the files of a directory, or the resources of a package of the classpath, under a URI prefix. api:http.server.routes.StaticResources[] is the handler of the HTTP server for static resources.

snippet::io.micronaut.docs.server.functional.StaticResourceRoutes[tags="resources", indent=0, title="Serving static resources under a prefix"]

<1> A `GET` route declares the URI prefix of the resources.
<2> The settings of the route are declared before the terminal, like for any route: here a filter, but also `where(...)`, `order(...)`, `attribute(...)`, `port(...)` or `executeOn(...)`. They apply to every resource of the route.
<3> `StaticResources.classpath(base)` serves the resources under a package of the classpath, inside jars too: `GET /assets/css/site.css` answers `functional-static/assets/css/site.css`.
<4> `cacheControl(...)` sets the `Cache-Control` header of the resources, here for files whose names change with their content. Without it, the header is the one of the files of the server, see `micronaut.server.responses.file`.
<5> `StaticResources.fileSystem(directory)` serves the files under a directory of the file system: `GET /site/hello.txt` answers the file `hello.txt` of the directory. Symbolic links that lead outside the directory are not followed.

The route registers two routes to the handler: `GET prefix`, which answers the index file of the directory, and `GET prefix/{+path}`, which answers the resource at `path`, relative to the prefix. Trailing slashes of the prefix are ignored. Like any `GET` route they have implicit `HEAD` routes, and they are ordinary routes: a more specific route of a controller or a handler under the prefix takes precedence.

A route of resources is declared in a group like any other route. `GET("")` serves the resources at the prefix of the group:

snippet::io.micronaut.docs.server.functional.StaticResourceRoutes[tags="group", indent=0, title="Static resources in a group"]

<1> The media types of the group do not apply to a route of resources: the content type of each resource follows its file name, here `text/html` for `index.html`, although the group produces JSON.
<2> The executor of the group applies. Without one, a route of resources runs on the blocking executor, because reading files and jars blocks: the executor of the route or of its groups replaces it.
<3> The filters of the group apply to the route of resources, like to the other routes of the group.
<4> `GET /manual` answers `index.html` of `functional-static/manual`.

==== Options

`StaticResources` is immutable: each option returns a copy.

* `classpath(base)`, `fileSystem(directory)` (a `String` or a `Path`), `of(locations...)` with the locations of `micronaut.router.static-resources`, e.g. `classpath:public` and `file:/var/www`, and `of(resourceLoaders...)`. With several locations, the first one that has a resource answers it. The classpath locations are of the context class loader of the thread that creates them, the class loader of the application. `fileSystem(directory)` fails with an `IllegalArgumentException` if the directory does not exist.
* `indexFile(name)`: the file answered for the prefix itself and for a path whose last segment has no extension and is a directory, e.g. `v1.2/docs`, `index.html` by default; `null` for none, then such a request is answered with `404`. It is the name of a file, without a slash.
* `cacheControl(value)`: the `Cache-Control` header of the resources.
* `pathVariable(name)`: the name of the path variable of the path of the resource, `path` by default: letters, digits and underscores.
* `hiddenFiles(serve)`: whether the hidden files are served, the paths with a segment that starts with a dot, e.g. `.env`, `.git/config` or `.well-known/security.txt`. By default they are not: such a path is answered with `404`.

snippet::io.micronaut.docs.server.functional.StaticResourceRoutes[tags="hidden", indent=0, title="Serving the hidden files"]

<1> `GET /public/.well-known/security.txt` answers the file, while `GET /site/.well-known/security.txt` of the route without the option answers `404`.

==== Responses

A file of the file system is answered as a api:http.server.types.files.SystemFile[], and any other resource, e.g. in a jar, as a api:http.server.types.files.StreamedFile[], so they are answered like the files of `micronaut.router.static-resources`:

* the content type follows the extension of the file name;
* the response has a `Last-Modified` header, and a request with a matching `If-Modified-Since` header is answered with `304`;
* a `Range` request for a file of the file system is answered with `206`. A resource of the classpath is a file of the file system when the classpath is a directory, e.g. while developing, and not in a jar, so it is answered with `206` while developing but not from the jar;
* a `HEAD` request is answered with the headers of a `GET` request, including `304` to a matching `If-Modified-Since`, without the content.

A request for a resource that no location has, or for a directory without an index file, is answered with `404`. So is a path that tries to leave the base: a `.` or `..` segment, a backslash, a colon, a NUL character, an absolute path, or a dot, slash or backslash encoded twice, e.g. `/assets/%252e%252e/secret.txt`, which the router decodes once. So is another spelling of a path, which the router could route elsewhere, e.g. past a more specific route under the prefix: an empty segment, as in `/assets/css//site.css`, an encoded slash in the path of the resource, as in `/assets/css%2fsite.css` or `/assets/..%2fsecret.txt`, and, on a file system that ignores the case, e.g. on macOS or Windows, a file spelled with another case, as in `/assets/CSS/SITE.CSS`: the names of the path under the base are compared exactly with the names their directories list. An encoded slash of the prefix is part of the prefix.

==== The rules of a route of resources

* `resources(...)` ends a route of `GET` only, e.g. `GET(uri)` or `route(HttpMethod.GET, uri)`. On any other route, e.g. `POST(uri)`, `any(uri)` or a route of `GET` and `POST`, it throws an `IllegalStateException` while the routes are built, so the application fails at startup. It throws one too on a route already ended by another terminal.
* The URI of the route is a prefix: it has no query or fragment, each of its variables matches one segment, e.g. `{tenant}`, `{id:\d+}` or `{tenant:[^/]+}`, not `{/version}`, `{+dir}`, `{dir:.*}` or `{dir:[a-z]*}`, which may match several segments or none, and the path variable of the handler is a plain name. Otherwise the route fails with an `IllegalArgumentException`. The prefix is a URI template: in a group whose `templates(...)` parse another language, `resources(...)` throws an `IllegalStateException`.
* The media types of its groups do not apply, but their filters, executor, conditions, order, port, annotations and attributes do.
* Reading the resources of the file system and of the classpath blocks, so the route runs on the blocking executor, unless the route or its groups declare an executor, e.g. `executeOn(...)` or `nonBlocking()`. A custom `ResourceHandler` that reads its resources without blocking returns `false` from `blocking()`.
* A `ResourceHandler` given to an ordinary route, e.g. `GET("/files/{+path}", StaticResources.fileSystem(directory))`, runs like a route of resources: on the blocking executor, without the media types of its groups, and not on a located route. A request whose other variables matched a slash, e.g. a decoded `%2F`, is answered with `404`.
* A route of resources is a route of an `HttpRoutes` bean: on a located route, see <<functionalRoutesLocators, Locator Routes>>, it throws an `IllegalStateException`.
* The prefix of the route, with the prefixes of its groups, does not have the path variable of the handler, e.g. `path("/tenants/{path}", ...)`: it throws an `IllegalStateException`. Give the handler another one with `pathVariable(...)`.

==== Static resources of the configuration

The static resources of the configuration, `micronaut.router.static-resources` (see <<staticResources, Serving Static Resources>>), and the routes of resources share the resolution of a path to a resource, api:web.router.resource.StaticResourceResolver[]: the order of the locations, the index file of a directory and the content type are the same. A route of resources rejects more paths, e.g. the hidden files and the other spellings of a path, and its classpath locations are of the context class loader of the thread that creates them.

Use the configuration to serve static resources without code, e.g. to change the locations per environment. Use a route of resources to give them the settings of a route: filters, conditions, an order, a port, an executor or a `Cache-Control` header, or to declare them with the other functional routes of a group.
