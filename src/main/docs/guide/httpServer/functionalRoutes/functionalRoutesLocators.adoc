A locator route routes the requests under a prefix to the routes of a target located at runtime, like a JAX-RS sub-resource locator. The routes of the target are declared by an api:web.router.builder.LocatedRoutes[], whose URIs are relative to the prefix and whose handlers receive the located target.

snippet::io.micronaut.docs.server.functional.LocatorRoutes[tags="imports,clazz", indent=0, title="Locator routes"]

<1> One `LocatedRoutes` instance for the routes of every located shop, kept in a field: the router declares its routes once, when the first shop is located, and every locator route that answers the same instance shares them.
<2> `locate(prefix, locator, routes)`: the locator finds the target of the request, here from a path variable of the prefix. `GET /shops/north/items/1` is answered by the route `/items/{index}` of the located routes, with the path variables of the prefix and of the route.
<3> `locateAsync` takes a locator that returns a `CompletionStage` of the target, e.g. loaded from a database: the request is matched with the located routes when the stage completes, without blocking the thread that matched it.
<4> `locate(prefix, locator, routesOf)`: a function selects the `LocatedRoutes` of each target, e.g. by its type or its state.
<5> `targetType()` is the type of the located targets: the handlers receive the target of that type, and a located target of another type fails the request.
<6> `routes(...)` declares the routes of a located shop on a api:web.router.builder.LocatedHttpRouteBuilder[], relative to the prefix. A route without a path is at the prefix itself.
<7> The handlers that do not take the target as an argument, e.g. the shortcuts such as `GET`, read it from their path variables with `LocatedRoutes.locatedTarget(pathVariables, type)`.

A locator that answers `null`, or a stage that completes with `null`, is a `404`. A locator that throws, or a failed stage, is handled by the error routes. When the located routes have no route for the rest of the path, the request is answered like a request that no route matches: `404`, or `405`, `415` or `406` if a located route matches the path with another method or media type. No other route of the application is tried.

The filters of the matched located route apply, after the filters of the groups of the locator route, and the server filters apply to the full path. Located routes may declare locator routes of their own, which locate again from the rest of the path, and error routes in their groups. They cannot declare global error or status routes, server filters or ports: those belong to the application routes, and declaring them fails the request that located the first target.

A synchronous locator runs while the request is matched, on the event loop, and must not block. The target is located once per request and kept for the rest of the request: a locator, synchronous or asynchronous, runs at most once per request, also when the request is answered with a `405` whose allowed methods are those of the located routes. Requests with a custom HTTP method are not located.

The server waits for the stage of an asynchronous locator without blocking, and cancels it when the client closes the connection before it completes. A CORS preflight request for a path under the prefix of an asynchronous locator is answered once the locator has located its target, with the methods of its located routes.
