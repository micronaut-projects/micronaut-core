Static resource resolution is enabled by default. The Micronaut framework supports resolving resources from the classpath or the file system.

See the information below for available configuration options:

include::{includedir}configurationProperties/io.micronaut.web.router.resource.StaticResourceConfiguration.adoc[]

TIP: Read the https://guides.micronaut.io/latest/micronaut-static-resources.html[Serving static resources in a Micronaut Application] guide, a step-by-step tutorial, to learn how to expose static resources such as CSS or images in a Micronaut Framework application.

TIP: To serve static resources with the settings of a route, e.g. filters, conditions or a `Cache-Control` header, declare them as a functional route, see <<functionalRoutesStaticResources, Static Resources>> of the functional routes.

=== Pre-compressed Files

Set `pre-compressed` on a mapping to serve compressed files produced at build time, e.g. by a frontend bundler, instead of compressing on every request:

[configuration]
----
micronaut:
  router:
    static-resources:
      default:
        paths: classpath:public
        mapping: /**
        pre-compressed: true
----

A request for `app.js` whose `Accept-Encoding` header allows it is served `app.js.br` (`br`), else `app.js.zst` (`zstd`), else `app.js.gz` (`gzip`). The highest `q` weight wins, ties follow that order, a coding with `q=0` is never chosen, and `identity` with a higher weight than a coding keeps the original file. A file without a sibling for an acceptable coding is served as it is, even when the request excludes `identity`, e.g. with `identity;q=0`: as RFC 9110 allows, the header is disregarded rather than answered with `406`, and the server may still compress the response on the fly.

With the option on, every response of the mapping has `Vary: Accept-Encoding` and a strong `ETag` that differs per encoding, so `If-None-Match` answers `304` for the representation the client holds. A pre-compressed response keeps the `Content-Type` of the original file, has the `Content-Encoding` of the sibling, and is not compressed again by the server.

A request with a `Range` header is always served the original, uncompressed file, so a range is a range of the original content.

The siblings are looked up by the same loader, with the same path checks, as the original file: a sibling never comes from outside the mapped location. Whether a classpath resource has a sibling is looked up once and remembered; files of a `file:` location are checked on every request. In a native image, include the compressed files in the image resources, e.g. with a `resource-config.json` pattern such as `public/.*\\.(br|gz|zst)`.

=== In-memory Cache

Set `cache-max-entries` on a mapping to keep the content of small resources in memory and serve them without reading the file:

[configuration]
----
micronaut:
  router:
    static-resources:
      default:
        paths: classpath:public
        mapping: /**
        cache-max-entries: 256
        cache-max-entry-size: 65536
----

Resources larger than `cache-max-entry-size` (64 KiB by default) are served from the file, as are requests with a `Range` header. When the cache is full, an entry is evicted to make room. A file of a `file:` location is checked on every request and loaded again when its last-modified time or length changes; classpath resources are cached as they are. Responses keep the file headers and conditional requests. A resource is loaded on its first request, which reads it on the thread that serves the request.

In a load test serving one file from a `file:` location (16 concurrent HTTP/1.1 clients on the same 4-core machine), the cache served 47% more requests per second for a 1 KiB file, 39% more for 16 KiB and 76% more for 64 KiB.
