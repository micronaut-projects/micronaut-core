Named event-loop transports are selected by the `transport` list on an event-loop configuration. The first registered, available factory in that list is selected. An external factory does not become the default merely because its bean is present. A list containing only an unavailable transport fails at startup.

Each listener can borrow a named worker group through `event-loop-group`. TCP and Unix listeners can also borrow a named acceptor group through `parent-event-loop-group`. When omitted, these properties inherit the server-wide groups. The selected transport supplies the listener's channels; the acceptor and worker groups must support those channels. QUIC uses its selected worker group and the existing QUIC implementation.

For example, TCP and QUIC can use separate NIO groups:

[configuration]
----
micronaut:
  netty:
    event-loops:
      tcp:
        transport: [nio]
      tcp-parent:
        transport: [nio]
      udp:
        transport: [nio]
  server:
    netty:
      listeners:
        tcp:
          family: TCP
          port: 8080
          event-loop-group: tcp
          parent-event-loop-group: tcp-parent
        quic:
          family: QUIC
          port: 8443
          ssl: true
          event-loop-group: udp
----

The QUIC listener also needs the existing server certificate configuration. Named groups remain owned by their registry: stopping a listener or stopping only the server does not shut down borrowed groups. Changes to listener group selection require a server restart.

The experimental api:http.netty.compression.NettyZlibCodecFactory[] SPI replaces construction of HTTP compression handlers independently of the selected transport. Supply one bean implementing this interface to replace the stock Netty factory. The factory receives the existing compression level, window size and memory level for encoding, and the wrapper mode and output allocation limit for decoding. It must return a fresh stateful handler for every call (or a sharable WebSocket extension handler) and release its resources through the handler lifecycle.

The selected factory is used for server response compression, request decompression, and managed client response decompression over HTTP/1, HTTP/2 and HTTP/3. Existing compression negotiation, thresholds, body limits and framing remain in Core. Default methods also support Brotli, Zstandard, and framed Snappy using stock Netty codecs. Override their availability and construction methods to supply an alternative implementation. A provider can advertise Brotli or Zstandard without initializing the optional stock JNI libraries. Brotli encoding uses quality 4 and text mode; Zstandard receives the configured compression level and maximum encode size and uses the Netty default block size. Framed Snappy retains Netty's default checksum policy. Existing providers implementing only gzip and deflate continue to use the stock defaults for these formats. A client built directly outside an application context uses stock codecs; set `zlibCodecFactory` on `DefaultHttpClient.builder()` to opt in explicitly.

TLS providers can extend api:http.netty.NettySslContextBuilder[] through the existing server and client SSL factories. Protected accessors expose key and trust material, protocols, cipher policy, ALPN and client authentication. Legacy server and client SSL builders also expose a protected `createSslContext` hook. Its default keeps existing material loading, builder customization and exception translation. An override must preserve configured TLS policy and required customizations, including ACME ALPN challenges. QUIC TLS retains its separate construction path.

The factory also creates server and managed client WebSocket compression extension handlers. These methods receive the endpoint's `@OnMessage(maxPayloadLength)` value, allowing providers to bound decompressed messages. Their defaults preserve Netty's existing extension negotiation, compression settings, allocation policy, and sharable client handler. Client compression must be enabled to invoke its provider hook; server handlers are created only for actual upgrades. Netty continues to handle WebSocket framing, masking, and UTF-8 validation.
