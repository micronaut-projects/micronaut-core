In test mode the development runtime runs a project's tests instead of its application: it watches the sources, compiles a change in process, and runs the tests the change can affect on a new generation, in the same JVM, so the library jars, the compilers, the JIT and expensive parent-tier state stay warm from one run to the next. The build plugins start it with `./gradlew mnTest` and `mvn mn:test`.

The manifest switches the mode and names the test sources, their output, and how they run:

[source,properties]
----
micronaut.dev.mode=test
micronaut.dev.test.sources.java=src/test/java
micronaut.dev.test.compile.java.output=build/classes/java/test
micronaut.dev.test.resources.config=src/test/resources
micronaut.dev.test.runner=junit-platform
micronaut.dev.test.selection=affected
micronaut.dev.test.reports=build/test-results/mnTest
micronaut.dev.test.filter=com.example.*Test
----

The test sources compile with the application's compilers, against the application's output, and both outputs are the reloadable tier, so a test and the classes it tests always come from one generation. Test-only libraries, JUnit and `micronaut-test` among them, are on the launch classpath. Without `test.compile-classpath` or `test.processor-path`, the tests compile with the application's.

A change runs the test classes that reference a changed class, directly or through other classes, as the class files tell, together with the classes that failed in their last run. Every test runs after a change of resources or configuration, when a changed class declares compile-time constants, which javac inlines without a reference to follow, or with `test.selection=all`. A change that does not compile runs nothing and is reported, and the last results stand. On a terminal single keys ask for runs: space runs the last tests again, `a` every test, `f` the failures, `w` turns watching on or off, and `q` exits with the last run's status. With `test.once=true` the tests run once and the launcher exits with their status.

Test execution is pluggable: a `TestRunner` registered as a service and named by `test.runner` runs the selected tests and streams their events. The JUnit Platform runner is built in and runs every engine on the classpath, from Jupiter and Spock to Pyronaut's pytest engine, when `junit-platform-launcher` is on the launch classpath. The events become JUnit XML reports, one `TEST-<class>.xml` per class in the Surefire shape, which every CI server and IDE reads, and go to every `TestReportListener` registered as a service, such as an HTML report.
