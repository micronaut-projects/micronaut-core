== The manifest

The launcher reads a manifest, a `java.util.Properties` file the build tool writes. The manifest names:

* the main class;
* the directories holding the compiled classes and resources, which form the reloadable tier;
* the compile and annotation processor classpaths;
* the source directories, by language;
* the resource directories, by kind.

[source,properties]
----
micronaut.dev.main-class=example.Application
micronaut.dev.reloadable=build/classes/java/main,build/resources/main
micronaut.dev.compile-classpath=@build/micronaut-dev/compile.argfile
micronaut.dev.processor-path=@build/micronaut-dev/processors.argfile
micronaut.dev.sources.java=src/main/java
micronaut.dev.resources.config=src/main/resources
micronaut.dev.resources.views=src/main/resources/views
micronaut.dev.resources.static=src/main/resources/static
micronaut.dev.compile.java.output=build/classes/java/main
micronaut.dev.retain=javax.sql.DataSource
----

The launcher reads the entries as follows:

* Relative paths resolve against the manifest's directory.
* `@file` reads a list from an argument file.
* A system property of the same name overrides an entry.

== Starting the launcher

The launcher is started with the runtime classpath, which holds the framework, the libraries and `micronaut-dev` itself. It does not hold the project's own class directories: those belong to the reloadable tier.

[source,bash]
----
java -cp @build/micronaut-dev/runtime.argfile io.micronaut.dev.MicronautDevMain --manifest build/micronaut-dev/dev.properties
----

The launcher compiles every language whose class output does not exist yet, so it works from a clean checkout. It then runs the application's own `main` on a thread of its own.

The application does what it always does, `Micronaut.run(Application.class, args)`. An `ApplicationContextConfigurer` the module ships gives the context:

* the reloadable loader;
* the `dev` environment;
* `micronaut.dev.enabled=true`;
* the beans retained from the previous generation.

TIP: Everything under the manifest's `micronaut.dev.` keys can be set as a system property. api:context.env.DevelopmentMode[] answers whether the application runs this way, so a bean can be conditioned on it with `@DevelopmentActive` (or `@DevelopmentInactive` for the opposite).
