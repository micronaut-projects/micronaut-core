An introspection describes the properties and methods of a type, not the types it extends. Some specifications need those too. Jakarta Bean Validation, for example, validates what a super class or an interface declares on its own terms, and has to know whether a type declares a method itself or inherits it.

Setting the `hierarchy` member of the ann:core.annotation.Introspected[] annotation to `true` records the hierarchy at compile time, so it is read without reflection through the `getTypeHierarchy()` method of api:core.beans.BeanIntrospection[]:

[source,java]
----
@Introspected(hierarchy = true)
public class Book extends Publication implements Comparable<Book> {
    public String getTitle() { ... }
    public int compareTo(Book other) { ... }
}
----

[source,java]
----
BeanTypeHierarchy hierarchy = introspection.getTypeHierarchy().orElseThrow();

hierarchy.getTypes();                           // [Book, Publication, ..., Comparable]
hierarchy.getSuperclass(Book.class);            // Optional[Publication]
hierarchy.getInterfaces(Book.class);            // [Comparable]
hierarchy.declaresMethod("compareTo", Book.class); // true
----

api:core.beans.BeanTypeHierarchy[] exposes:

* `getTypes()` - the type and every super class and interface of it, each once, depth first: the super class and its super types, then the interfaces and theirs. `Object` is reported as a super class but not described itself.
* `getSuperclass(type)` and `getInterfaces(type)` - what a type of the hierarchy extends and implements itself
* `getDeclaredMethods()`, `findDeclaredMethod(name, parameterTypes)` and `declaresMethod(name, parameterTypes)` - the instance methods the type declares that are not private, whether or not they are bean methods, matched by their erased signature without loading the parameter types

The hierarchy is the one the compiler saw. A type whose class cannot be loaded at runtime is left out.

IMPORTANT: `hierarchy` defaults to `false` because the additional metadata increases the size of the generated introspection. It is recorded in the annotation metadata of the introspection, so it has no effect when `annotationMetadata` is set to `false`.
