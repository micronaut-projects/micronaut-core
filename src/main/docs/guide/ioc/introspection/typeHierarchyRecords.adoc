A bean introspection describes a bean, and its <<introspectionHierarchy, type hierarchy>> is raw. Some code needs the generic hierarchy of classes that are not beans: the class of an event payload whose generic supertypes decide which observers hear it, a class that appears as a type argument or a bound, or a class of a library or of the JDK. The ann:core.annotation.TypeHierarchyImport[] annotation imports that hierarchy at compile time, as it is declared, so that it is read without reflection through api:core.type.TypeHierarchies[]:

The hierarchy is made of api:core.type.Argument[] instances: a type variable is a api:core.type.GenericPlaceholder[] with its bounds, a wildcard a api:core.type.WildcardArgument[], a type written without its type arguments a raw type. The record holds the super types of the type as the compiler listed them (`ClassElement.getAllSuperTypes()`), every one of them that the record can name (see below), with their type arguments written in the variables of the type, so the hierarchy is walked once, at compile time. `getTypeClosure(parameterization)` substitutes the actual type arguments into each entry, erasing all of them for a raw parameterization as the Java Language Specification does, each type once and `Object` last.

A record is a small generated class, written once for each type and package it is written into, found through the `META-INF/micronaut` service entries like a bean definition is, and loaded only when its type is asked for. A compile-time visitor imports a type with `importTypeHierarchy` of api:inject.visitor.VisitorContext[], which returns the name of the record. A visitor that must know whether the record is complete, because it keeps a description of its own of what the record leaves out, calls `recordTypeHierarchy` instead: it writes the same record and returns a api:inject.visitor.TypeHierarchyRecord[] with the name of the record and the names of the super types it leaves out, the same names the record lists at run time (see below). `tryRecordTypeHierarchy` returns empty, and writes nothing, for a type no record can describe (see the end of this section), where the other two fail the compilation with the reason.

A record is written into the package of the class that imports the type, or under it: the record of a class of the same package is `com.example.$Payload$TypeHierarchy`, and the record of a class of another package goes into a sub-package of the importing package named after the package of the type, `com.example.$$java.util.$ArrayList$TypeHierarchy` for `java.util.ArrayList` imported from `com.example`. Only a type that is itself not public is recorded in its own package, the one package that can name it; a public class nested in a class that is not public counts as not public. A type of the JDK that is not public cannot be recorded.

A record can only name the classes that are public or of the package it is written for, the importing package. A super type whose declaration names any other class is left out of the record, with the types above it kept:

* a super type whose class is neither, such as the package-private `java.lang.AbstractStringBuilder` that `StringBuilder` extends or a package-private base class of a library
* a public super type whose type arguments name such a class, at any depth, `Supplier<List<Hidden>>` for a package-private `Hidden`, or a class nested in one

Such a super type is missing from `getSuperTypes()` and from `getTypeClosure(...)`, and from `getGenericSuperclass()` or `getGenericInterfaces()` when it is a direct super type. `getOmittedSuperTypeNames()` lists the name of the class of each, without its type arguments, so that code which knows the class from its own package can still tell that it is a super type. The names are erased evidence of membership only, not generic metadata: `Base<String>` and `Base<Integer>` are both `p.Base`, and code that needs the type arguments of such a super type keeps a record of its own, written in the package of the class. A record written by a processor that predates the names lists none, which says nothing about what it left out.

A type imported from several packages has a record in each, and they can leave out different super types. `TypeHierarchies` finds the record in the package of the type when there is one, and otherwise the one that left out the fewest super types.

Some declarations cannot be recorded at all, and fail the compilation: a type whose variables are bounded by a class the record cannot name, since leaving the bound out would change what the variable is bounded by and erases to, and a type that is, or extends, an inner class of a generic class (`Outer<T>.Inner`), whose variables the arguments of the enclosing class bind and a record does not keep.
