## Migration Rules

- Do not define local copies of Micronaut annotation helpers such as `micronaut_annotation`, `SingleResult`, or custom annotation shims in docs snippets. Standard Micronaut annotations are generated by `micronaut_transformer.py` from imports. If Python cannot express the import path, keep the intended annotation commented out with a TODO and track it below.
- Do not add Java-style getters or setters to Python docs models. Prefer `@dataclass` models with idiomatic Python attributes, and adapt tests/snippets around attributes or maps instead of adding `getX`/`setX` methods.
- For Reactor APIs whose Java method names are Python keywords, use `getattr`, for example `getattr(Flux, "from")(publisher)` and `getattr(Mono, "from")(publisher)`. The GraalPy underscore form is not reliable for Reactor `Flux.from` / `Mono.from`.
- For annotation/decorator members whose names are Python keywords, use keyword-argument expansion, for example `@Error(**{"global": True})`.
